# Промт для AI-агента: разработка веб-приложения для настройки ПИД-регуляторов

## Задача
Разработать веб-приложение на **Flask** (Python) для автоматической настройки коэффициентов ПИД-регулятора по загруженным данным технологического процесса в формате CSV. Приложение должно предоставлять выбор методов расчёта, визуализацию, возможность ручной корректировки и экспорт отчётов (PDF, Excel).

---

## Требования к функциональности

### 1. Загрузка данных
- CSV-файл с разделителем `;` (точка с запятой) и десятичной запятой `,`.
- Обязательные колонки: `PV` (регулируемая величина), `SP` (задание), `CV` (выход регулятора, 0-100%).
- Опционально: столбец времени (`Time`) – если отсутствует, используется номер строки.
- Предобработка:
  - Интерполяция на равномерную временную сетку (шаг задаётся пользователем или автоматически определяется по медианному интервалу).
  - Медианная фильтрация (окно 5–7 точек) для подавления шума.
  - Обнаружение ступенчатого изменения `SP` (порог – 5% от размаха).

### 2. Идентификация модели объекта
Определить параметры модели **FOPDT** (звено первого порядка с запаздыванием):
- `K` – коэффициент усиления.
- `T` – постоянная времени.
- `τ` – чистое запаздывание.
А также, если возможно, критические параметры для замкнутого контура:
- `Kкр` – критический коэффициент усиления.
- `Tкр` – период автоколебаний.

**Методы идентификации** (выбор пользователя):
- По переходной характеристике (ступенчатое изменение `SP`) – метод двух точек или касательной.
- По произвольному сигналу – аппроксимация FOPDT методом наименьших квадратов (scipy.optimize.curve_fit).
- Релейный метод (если в данных есть автоколебания).

### 3. Расчёт коэффициентов ПИД
Поддерживаемые методы настройки (выбор пользователя):
- Зиглера–Николса (разомкнутый контур – по `K, T, τ`).
- Зиглера–Николса (замкнутый контур – по `Kкр, Tкр`).
- Чен–Хрон (CHR) – с настройкой на минимальное перерегулирование или быстрое затухание.
- Внутренняя модель (IMC) – с параметром λ (задаётся пользователем).
- Оптимизационный (минимизация ITAE) – опционально.

**Типы регуляторов**: P, PI, PID, PID с фильтром на D-составляющей.

### 4. Визуализация (интерактивные графики)
Использовать **Plotly.js** (встраивание в HTML через JSON). Три графика:
1. Исходные данные: `PV, SP, CV` по времени.
2. Идентифицированная модель: сравнение реальной переходной характеристики и модели FOPDT.
3. Симуляция замкнутой системы с рассчитанными коэффициентами: отклик `PV` на ступеньку `SP` (или на массив `SP` из данных).

Графики должны обновляться без перезагрузки страницы при смене метода/типа (AJAX).

### 5. Интерфейс и локализация
- Весь интерфейс на **русском языке**.
- Использовать **Bootstrap 5** для адаптивного дизайна.
- Страницы:
  - **Главная** – загрузка файла, выбор режима идентификации (авто/ручной).
  - **Результаты** – графики и панель управления (выбор метода, типа, кнопка пересчёта, отображение коэффициентов, кнопки для ручной корректировки и экспорта).
  - **Ручная корректировка** – форма с полями `Kp, Ti, Td`, сохранение изменений с пересчётом симуляции.

### 6. Экспорт отчётов
- **PDF** (через `reportlab`): титульный лист, таблица параметров и коэффициентов, графики (встроены как PNG).
- **Excel** (через `openpyxl`): лист с исходными данными, лист с параметрами, лист с результатами симуляции.

### 7. Хранение данных
- Использовать **Flask session** для хранения данных текущего пользователя (однопользовательский режим).
- Загруженные файлы временно сохраняются в папке `uploads/`, отчёты генерируются на лету и отправляются на скачивание.

## Технологический стек
- **Backend**: Flask, Pandas, NumPy, SciPy, Matplotlib (для сохранения графиков в PNG), ReportLab, OpenPyXL.
- **Frontend**: Bootstrap 5, Plotly.js, jQuery (для AJAX).
- **Вспомогательные**: python-dotenv, werkzeug (для безопасной загрузки файлов).

## Требования к коду
- Код должен быть чистым, модульным, с комментариями на русском или английском (пояснениями).
- Обработка ошибок: валидация файла, недостающие колонки, невозможность идентификации – вывод понятных сообщений пользователю.
- Все численные расчёты должны быть устойчивы к выбросам и пропускам (интерполяция и фильтрация).
- Симуляция должна использовать дискретные уравнения с шагом, соответствующим интерполированным данным.

## Дополнительные рекомендации
- Для генерации графиков в PDF использовать `plotly.io.to_image()` или временное сохранение в PNG через Matplotlib.
- Для AJAX-обновления: при смене метода отправлять POST на `/results` с JSON, возвращать новые коэффициенты и данные для графика симуляции, затем обновлять Plotly-графики через `Plotly.react()`.
- На странице результатов предусмотреть индикацию загрузки при пересчёте.
